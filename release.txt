Change log
----------

v0.6.1b
- modified to support DCAM-API 17.11.5373 and HVC 4.2.11 (BinaryTIFF 0.3.2b)

v0.6.1a
- added support for Ti2
- fixed timing issues with (sub-)millisecond exposure times

v0.6.1 (6/20/2016)
- moved hardcoded sync device address to config file
- added additional stage controls (set/return home, abort motion)

v0.6.0 (6/28/2016)
- merged v0.5.5 (old microscope) and v0.5.7 (new microscope)
- added "Virtual Microscope" actor as abstraction layer for specific microscope model
- fixed incorrect assignment of Cy5 emission filter on new microscope
- added support for additional multi-excitation settings
- fixed detection setting behavior when using multi-line excitation
- added warning when file path is too long

v0.5.7 (6/17/2016)
- added support for simultaneous Cy2/Cy3 excitation

v0.5.6 (03/05/2015)
NOTE: this is a separate branch that works only with the new microscope
(needs to be merged for next version)
- added support for Nikon Eclipse-Ti (new microscope)

v0.5.5 (02/09/2015)
- fixed bug interfering with the use of Cy5/Cy7 shutters in "show live"

v0.5.4 (02/03/2015)
- improved viewer performance by replacing global variables with lossy
single-element queue for frame data transfer and adjusting timeouts
- added ability to disable/enable "separate live settings" on the fly

v0.5.3 (not released)
- implemented check if enough space is available on volume
- modified configuration files for replaced cameras
- fixed a live viewer bug
- fixed a bug related to saving movies
- block "show live" while "stream acquisition" is running
- fixed bug in syringe pump volume setting

v0.5.2 (not released)
- implemented experimental focus indicator

v0.5.1 (not released)
- changed default configuration to reflect that defective Cy5 camera was
replaced with Cy2 camera
- improved live display when only one camera is turned on
- using new BinaryTIFF v0.3.2 for correct saving of single-channel movies
- improved live viewer behavior by locking time-critical global variables
with semaphores
- eliminated display of white blank frame or frame from previous live
window when starting show live
- added (default) option to turn pixel correction on for show live and
off for stream acquisition
- limited display range to current bit depth
- cameras can now be turned on and off without logging out of windows
- fixed inverted colormap bug

v0.5.0 (not released)
- improved performance of live viewer by moving display update and running
calculations (histogram, scaling etc.) to asynchronous loops
- added "asylum" color map
- set progress dialog to remain visible when LabVIEW loses focus
- improved handling of progress bars
- added BinaryTIFF function to reset frame counter global variable
- added shutdown splash screen
- fixed bug that caused LabVIEW to stay in memory in unresponsive state 
after closing Flash Gordon (by making sure that all cameras are shut down
before attempting to close the driver)
- eliminated 2-second delay when saving a Tiff file
- added a dialog during startup that displays the detected cameras (11/13)

v0.4.4 (not released)
- allow saving of partial movie when stream is canceled
- add "custom length" button to photobleaching dialog
- added "advanced" option to skip frames from beginning of movie (defaults 
to one frame to remove the corrupted initial sCMOS frame)
- use new version of BinaryTIFF (v0.3.1) to accomplish frame skipping

v0.4.3a (11/11/2014)
- fixed bug that led to movies being saved with all zeros
- fixed a bug in the progress bar display

v0.4.3 (11/06/2014)
- added option to cancel acquisition
- minor code improvements
- temporarily added a "Photobleach 3 mm" configuration file (this will be
replaced by a custom photobleach button in a future version)

v0.4.2 (11/05/2014)
- fixed bug that required closing and restarting program to detect cameras
- removed zero-valued pixels from histogram to improve display/autoscale
- corrected arrangement of channels
- tested handling of 4 channels (after adding 4th framegrabber card to PC)
- fixed bug that led to corrupt files when acquiring with 2 cameras

v0.4.1 (10/23/2014)
- added cubehelix color map (https://www.mrao.cam.ac.uk/~dag/CUBEHELIX/)
- improved live viewer zoom feature (and removed confusing LabVIEW graph tool)
- improved live viewer autoscale feature by ignoring fixed percentages from
top and bottom of histogram
- overlay active colormap onto histogram
- removed obsolete "focus" feature

v0.4.0 (10/21/2014)
- added support for XML-based configuration files for user-selectable 
hardware settings
- added support for XML-based initialization file for non-user-selectable 
program settings; saves program state between subsequent sessions
- added support for up to 4 cameras (Flash 4.0 v2)
- implemented channel identification based on detected camera serial numbers
- using new version of BinaryTIFF (v0.3.0) to handle data from up to 4 cameras
- added support for fractional exposure times (e.g. 2.5 ms) by using the
new "High Resolution Relative Seconds" function in LabVIEW
- switched the output mode of the NI-DAQ device from "open collector"
(default) to "active drive" to allow triggering a flexible number of cameras
without modifications to the trigger circuit
- overhauled alignment mode
- added support for 730 nm laser shutter
- fixed a viewer bug that caused incorrect aspect ratios when zoomed in
- added setting for optional Flash 4.0 pixel correction ("Advanced" tab)
- added support for Flash 4.0 "Fast Synchronous Readout" (slightly faster
external trigger mode)
- changed Flash 4.0 output trigger source from "Read End" to "VSync"
for better oscilloscope display
- added "About This Version" dialog
- added "Suggest Feature or Report Bug" dialog
- provided a "Reset View" button to reset to full field (and work around a bug
in the zoom/scaling functionality)

v0.3.0 (09/30/2014)
- added support for the PHD Ultra pump
- added a timed, automated injection mode for real-time delivery experiments

v0.2.2 (09/16/2014)
- fixed bug in the "100 um back" function
- handled case when no file name or invalid path is entered

v0.2.1 (09/05/2014)
- prevent user from trying to cancel "Stream Acquisition" (which is
currently unsupported)
- fixed bug in "Auto-Increment File Name"

v0.2.0 (09/04/2014)
- implemented "Auto-Increment File Name" and "Auto-Advance Field Of View"
- several minor improvements

v0.1.7
- added injection countdown timer
- fixed a bug that prevented standalone (.exe) version from running

v0.1.6
- fixed an error caused by the "File Name" field accepting multi-line input
- enabled changing exposure time while live mode is running
- renamed "Live Preview" to "Show Live" to match MetaMorph
- moved "Scan Mode" to advanced tab
- fixed a bug that occurred when trying to run "Stream Acquisition" while 
"Show Live" is running
- temporarily disabled sizing of live viewer until improved scaling behavior
is implemented
- fixed a bug that caused some movies to be saved incorrectly (with frames
containing all zeros)
- improved alignment mode

v0.1.5
- fixed several bugs that occasionally led to files not being saved or stream
acquisition being terminated right after start of acquisition
- added more elegant handling of the case when the user tries to save to a file
that already exists
- using new, little-endian version of BinaryTIFF (v0.2.0) to increase write speed
(about 1.5x faster)
- added focus and pan buttons for live viewer


Known issues
------------
- parallel loops in viewer are not completely independent, leading to choppy
performance
? number of cameras can be increased, but not decreased without logging off
and back on
- live mode sometimes gets stuck/takes a long time to start cameras
- changing exposure time in live mode responds very slowly
? focus indicator stays open when live preview is closed
? "stream acquisition" and "show live" not locked while movie is being saved
- program crashes with no message if expected hardware is not turned on
- waiting for cameras may get stuck in endless loop if cameras turned off
- built (.exe) version is not functional
? auto-increment may not work in certain cases when file name already exists
? pixel correction gets turned off randomly (usually noticed after photobleaching)
(apparently this happens when exposure time is changed without restarting 
show live)
- injection timing may have changed over the last few updates
- long file names should be possible by renaming final files
- "reset view" needs to be used frequently in multi-color mode
